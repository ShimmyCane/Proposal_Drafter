# S+Y Studio Proposal Framework

## What the actual proposal examples teach us

The Gardena example is a useful corrective to the more generic AI-generated proposal approach. The actual client-authored draft is not a broad design proposal; it is a focused, limited-service architectural proposal built around a permit-ready builder's set, subdivision logic, mirrored duplex plan assumptions, city and fire review, and milestone billing.

The framework should therefore reflect two realities:

1. Many client proposals are narrower and more specific than a typical architecture studio template.
2. The strongest proposal language is built from actual project assumptions, not generic placeholders.

This means the planning workflow should help us identify whether the work is:
- design-led,
- permit-led,
- entitlement / planning support,
- or a limited architecture package for a builder or developer.

The workflow should not assume a default path. Instead, it should prompt the user to identify the project path before drafting. If the project type is unclear, ask which of these applies before writing the proposal.

---

## Prompt-first project path selection

Before drafting, ask:
- Is this a full design project, a permit-set project, a planning-support project, or a hybrid?
- Are the plans based on existing precedent, mirrored duplexes, or a fresh design?
- Are we responding to a builder / developer requirement, a planning pathway, or a full design commission?

This keeps the proposal aligned with the actual client request instead of pushing a generic design narrative.

---

## The key difference between an AI draft and the real proposal

A generic AI draft tends to:
- assume a broad design process,
- include a discovery phase even when the client wants a fixed-scope permit package,
- describe risks and unknowns in a more open-ended way,
- use vague planning language without project-specific constraints,
- present fee ranges rather than a clear milestone-based fee structure.

The actual Gardena proposal is more grounded in the facts:
- 6-parcel subdivision logic using SB 684 / SB 1123 logic
- 3-story duplexes on each parcel
- approximately 2,500 sf per duplex
- mirrored duplex plans, with selected interior finishes by the builder
- limited architectural services focused on permit set production and agency review
- defined exclusions for consultants, fire sprinklers, plotting, and construction admin
- direct milestone payments with a fixed total fee of $65,000

This should become the default check for future work: compare the AI draft to the real client facts before sending a proposal.

## Recommended S+Y proposal structure

### 1. Cover Letter / Introduction
Include:
- date
- client name and company
- direct project description
- brief statement of intent
- clear project type and service level

Use wording like:
- "This is a draft proposal for limited architectural services to prepare a builder's permit set for the Gardena lot."

### 2. Project Description
Include:
- site / parcel information
- project type and scale
- current design assumptions and whether the project is based on mirrored plans or prior model work
- constraints such as planning pathway, permit process, existing conditions, or entitlement logic
- whether the work is permit-first, planning-first, or design-assist

Suggested template:
- Project type: [small-lot subdivision / duplex / permit set / entitlement support / builder design-assist]
- Site / parcel logic: [describe lot split, SB 684 / SB 1123, or similar path]
- Existing conditions: [describe site status and known assumptions]
- Design assumption: [mirrored plans / similar unit layouts / builder-selected finishes]
- Constraints: [permit review, planning path, consultant timing, deferred submittals]

### 3. Scope of Work by Phase
Organize the scope around actual tasks, not abstract phase names alone.

Common structure for this type of project:
- Phase I – Site and zoning analysis
- Phase II – Planning / entitlement support
- Phase III – Construction drawings and permit set
- Phase IV – Agency coordination and plan check support

For each phase include:
- what services are actually included,
- what is not included,
- key deliverables,
- required client coordination and consultant input,
- expected agency review.

### 4. Clarifications and Exclusions
This section should be explicit and project-based.

Use it to state:
- what consultants are excluded,
- what submittals are deferred,
- what printing / plotting / reproduction expenses are reimbursable,
- whether construction administration is excluded,
- what additional services are billed hourly,
- what owner responsibilities are required.

This is often more helpful than a long list of generic exclusions.

### 5. Fee and Payment Schedule
Use a straightforward fixed-fee structure when possible, paired with milestone billing.

Best practice:
- state a clear total fee,
- define deposit and milestone thresholds,
- tie each milestone to a recognizable project event,
- explain whether additional services are hourly or change-order based,
- make sure the fee reflects the actual level of design, review, and agency coordination.

This is usually stronger than a broad fee range.

### 6. Timeline and Milestones
A realistic schedule should reflect:
- client review time,
- consultant coordination time,
- planning approval process,
- city plan check timing,
- whether permit review is ministerial or discretionary.

Good language:
- estimated review / approval timeline,
- major milestone dates,
- schedule assumptions,
- likely delays due to agency review or consultant input.

### 7. General Conditions and Legal Terms
Include only the language that matters to the actual project.

Typical issues to include:
- document sharing method (such as Box or shared drive),
- ownership of drawings and instruments of service,
- limited license to use the drawings for the project,
- reliance language for sealed documents,
- termination rights and compensation for work done to date,
- proposal validity period.

This should be concise and clear, not overloaded with unnecessary legal language.

### 8. Signature Block
Include:
- Owner signature lines,
- Architect signature lines,
- date fields,
- contact information,
- project name or address.

## S+Y Studio-specific drafting notes

For S+Y Studio proposals, it helps to emphasize:
- project realism over template language,
- scope clarity and direct assumptions,
- permit-set logic and agency coordination,
- fixed-fee logic supported by milestones,
- explicit responsibilities of owner, consultants, and architect,
- professional but direct tone,
- a strong distinction between included work and additional services,
- the fact that design decisions and consultant timing are often the drivers of scope and schedule.

## Project-type guidance

### Limited permit-set / builder's set projects
Use this when the project is driven by:
- a permit-ready set,
- mirrored or similar unit planning,
- builder-selected finishes,
- deferred design-build systems,
- tight coordination with city and fire agencies.

This type of proposal should:
- limit scope to the actual permit package,
- clearly note the assumptions about plan repetition and finish selection,
- identify owner consultant responsibilities,
- include a milestone payment schedule,
- state what is deferred, reimbursable, or excluded.

Suggested starter block for a standard project of this type:
- Project path: [Permit-led / limited service]
- Project type: [Small-lot subdivision / duplex / permit set]
- Base scope: [site and zoning review, permit drawings, agency coordination, RTI support]
- Exclusions: [structural, MEP, civil, landscape, full construction admin, plotting, deferred submittals unless specified]
- Pricing: [fixed fee + milestone billing]

### Entitlement / planning support projects
Use this when a lot split, site plan review, or project approval path is central.

This type of proposal should:
- include the planning pathway and likely agency review,
- separate planning support from final permit set work,
- identify whether the project may involve discretionary review,
- note the risks of additional rounds or modified scope.

### Full design / design-build projects
Use this when the work includes significant design evolution, concept, and documentation work.

This type of proposal should:
- include phased design development 
- define design revisions and review rounds
- include consultant coordination expectations
- avoid reading like a permit-only proposal

## Minimal working checklist

Use this checklist before sending a proposal:
- [ ] Project description reflects the real project facts
- [ ] Scope is written in actual phases or tasks, not generic placeholders
- [ ] Deliverables are explicit and tied to the permit or planning path
- [ ] Fee and payment schedule are stated and realistic
- [ ] Timeline assumptions are clear
- [ ] Included and excluded services are unambiguous
- [ ] Consultant and owner responsibilities are defined
- [ ] The proposal does not overstate design scope if the project is permit-led
- [ ] The proposal reflects the client’s actual language and project logic
- [ ] The proposal is reviewed against a real project narrative before final submission

---

## AI review / comparison checklist

Use this before accepting or revising an AI-generated proposal:
- [ ] Does the proposal match the client’s real project type and scope?
- [ ] Is the proposal using the correct project path: permit-led, planning, design-led, or hybrid?
- [ ] Are the assumptions and exclusions grounded in the actual project facts?
- [ ] Does the fee structure match the actual work and milestones?
- [ ] Are the owner and consultant responsibilities clearly separated?
- [ ] Does the proposal avoid generic design language when the client asked for a limited permit package?
- [ ] Has the AI draft been compared against the client-authored narrative before finalization?
